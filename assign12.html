Assignment 45: localStorage vs sessionStorage

Both Web Storage APIs store key-value pairs in the browser. Values are stored as strings.

Feature localStorage sessionStorage
Lifetime Until cleared or removed Usually until the tab session ends
Page reload Data remains Data remains in the same tab
Tab behavior Shared by same-origin pages Separate per tab session
Data format String key-value pairs String key-value pairs
Common use Theme and user preferences Temporary tab-specific state
API example localStorage.setItem() sessionStorage.setItem()

Comparison Note

Use localStorage when information should survive browser restarts, such as display preferences. Use sessionStorage for temporary data needed only during a tab session. Neither API should store passwords or sensitive authentication information.

Assignment 48: Load–Update–Save–Render Lifecycle

This lifecycle keeps an application's data consistent with its saved state.

  1. Load

    Read saved data from localStorage when the application starts.

  2. Update

    Modify the data in JavaScript when the user performs an action.

  3. Save

    Convert the updated data to JSON and write it to localStorage.

  4. Render

    Update the visible interface to match the current data.
